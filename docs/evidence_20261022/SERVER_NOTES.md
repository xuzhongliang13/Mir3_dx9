| 角色 | A | B | 等级 | C | 真实性别(用户确认) |

- 等级字段正确（40 / 1）→ 切分位置无误

## 背包物品不显示的根因（2026-10-22 定位）

**现象**: 传奇3 上背包格子空、物品不显示；`bag_dump.txt` 从未生成
→ 说明 `SM_BAGITEMS` 处理函数**根本没被执行**。

**根因**: `CGameProcess::OnMessageReceive` 里的 `[#19-FIX]` 长度校验
（由审计提交 `7c5caf3` 引入）把大包**静默丢弃**:

```cpp
int fragLen = (int)(pEnd - pStart - 1);
if ( fragLen > 0 && fragLen <= _DEFBLOCKSIZE + _MAX_STRING_LEN )   // <= 1040
    OnSocketMessageReceive( pStart + 1 );
```

**尺寸计算**（`CLIENTITEMRCD` 实测 81 字节）:

| 背包物品数 | 解码字节 | 线上字符数(含16头) | 是否丢弃 |
|---|---|---|---|
| 1 | 81 | 124 | ok |
| 5 | 405 | 556 | ok |
| 9 | 729 | 988 | ok |
| **10** | 810 | **1096** | **丢弃** |
| 20 | 1620 | 2176 | 丢弃 |
| 46 | 3726 | 4984 | 丢弃 |

线上字符数 ≈ 解码字节 × 8/6（用真实 `SM_LOGON` 验证: 52 wire / 39 decoded = 1.333 ✓）

**临界点: 物品数 ≥ 10 即被丢弃。** 而客户端自身背包容量是 `_MAX_INVEN_ITEM=46`。

**深层问题**: `PACKETMSG.szEncodeData[_MAX_STRING_LEN]` = **1024 字节**，
而合法的 `SM_BAGITEMS` 负载可达 46×81 = 3726 字节。
即**缓冲区本身就装不下本协议自己的合法包**，校验只是把"溢出"变成了"静默丢包"。

相关代码位置:
- `Common/EnDecode.h`: `CHAR szEncodeData[_MAX_STRING_LEN]` (1024)
- 各 handler 用 `lstrcpy(lpPacketMsg->szEncodeData, ...)` 拷贝（无长度限制）
- `Common/ClientSocket.cpp:470`: 接收缓冲 `char recvBuf[8192]`
